# 곡을 열면 먼저 다 해석하고, 그 다음에 재생

2026-08-19

## 문제

곡을 열면 플레이어가 곧바로 뜨고 음악이 시작되며, 해석은 그 뒤에서 줄
단위로 채워진다. 화면 아래에는 진행바가 계속 떠 있고, 번역은 읽는 도중에
하나씩 나타난다. 완성되지 않은 화면을 읽게 되는 것이 이 앱의 첫인상이다.

## 결정

곡을 고르면 **전곡 해석을 끝낸 뒤에** 플레이 화면으로 넘어간다. 준비가
끝나기 전에는 재생도 시작하지 않는다.

이 결정에는 대가가 있고, 그것을 알고 고른 것이다. 시뮬레이터 측정으로 한
줄에 약 12초가 걸린다(`夜に駆ける` 56줄, 13:09 0/56 → 13:13 20/56). 처음
여는 곡은 로딩이 **10분대**가 된다. 곡당 한 번이고 결과는 영구 저장되므로,
매번 지저분한 화면을 보는 것보다 한 번 기다리는 편이 낫다고 판단했다.

측정값은 시뮬레이터 기준이며 실기기 Neural Engine에서는 다를 수 있다.
실기기 측정은 하지 않았다.

## 흐름

```
곡 선택
  └─ 커버 표시 (지금과 동일)
       ├─ 준비 단계 ── 아트워크 · 제목 · 진행률 · 남은 시간 · 「중단」
       │                  가사 로딩 → 남은 줄 해석 (한 바퀴)
       │                  └─ 중단 → 커버 닫힘, 검색 화면으로
       └─ 준비 완료 ── nowPlaying 확정 → 재생 시작 → 가사 화면
```

### 화면을 새로 만들지 않는다

준비 단계는 `PlayerScreen` 안의 한 상태로 둔다. 세션, 가사 로딩, 해석이
이미 그곳에 살고 있어서 별도 화면을 세우는 것보다 옮길 것이 훨씬 적다.
`fullScreenCover`는 지금 그대로 쓰고, 준비가 끝나기 전에는 가사 화면 대신
준비 화면이 그려진다.

### 재생과 `nowPlaying`은 준비 완료 시점으로 미룬다

지금은 `AppModel.open`이 즉시 `nowPlaying`을 세워 미니플레이어를 만든다.
이것을 준비 완료 뒤로 옮긴다. 그러지 않으면 중단하고 나갔을 때 한 번도
울리지 않은 곡의 미니플레이어가 남는다.

부수 효과: 다른 곡을 듣던 중에 새 곡을 고르면 **준비하는 동안 듣던 곡이
계속 재생된다.** 준비 단계는 플레이어를 건드리지 않기 때문이다. 10분이
완전한 정적이 되지 않으므로 이 동작은 유지한다.

### 준비는 정확히 한 바퀴만 돈다

모델이 실패한 줄은 최종 답으로 치지 않아 계속 미완료로 남는다(`6f816e9`).
완료될 때까지 반복하면 계속 실패하는 줄 하나가 입장을 영원히 막는다.

준비는 남은 줄을 한 바퀴 돌고 끝낸다. 성공률과 무관하게 끝낸다. 남은 줄은
다음에 곡을 다시 열 때 이어서 하고, 플레이어 메뉴의 「남은 줄 분석」은 그
잔여분을 위해 남긴다.

### 진행 표시

- 진행률 `12/56`
- **남은 시간 추정** — 실제 줄당 소요의 이동 평균으로 계산한다. 10분을
  기다리게 하면서 얼마나 남았는지 알려주지 않을 수는 없다.
- 「중단」 — 커버를 닫고 검색 화면으로 돌아간다.

진행분은 지금도 줄 단위로 저장되므로 중단해도 버려지지 않는다.

### 갈래별 동작

| 상황 | 동작 |
|---|---|
| 이미 해석한 곡 | 남은 줄이 없어 준비가 즉시 통과, 바로 가사 화면 |
| 일부만 해석된 곡 | 남은 줄만 한 바퀴 |
| 가사를 못 찾음 | 해석할 것이 없으므로 준비를 건너뛰고 플레이어로 — 지금의 「다시 찾기」 화면을 그대로 보여준다 |
| 「다시 찾기」 성공 | 준비 단계로 되돌아가 해석한 뒤 다시 들어온다 |
| Apple Intelligence 없음 | 사전 경로는 모델 호출이 없어 준비가 거의 즉시 끝난다 |

「다시 찾기」 성공 시 준비 단계로 되돌리는 것은 "플레이어에는 완성된 곡만
보인다"는 규칙을 한 갈래로 유지하기 위한 것이다.

## 검증

순수 로직은 단위 테스트로 덮는다. 앱 타깃은 테스트 대상이 아니므로, 아래
둘은 JustCore/JustSensei에 두어 테스트 가능하게 만든다.

- **남은 시간 추정** — 소요 표본에서 남은 줄 수를 곱해 내는 순수 함수.
  표본이 없을 때, 하나일 때, 튀는 값이 섞였을 때를 덮는다.
- **한 바퀴 규칙** — 실패한 줄이 한 바퀴 뒤에도 미완료로 남고, 준비는
  그럼에도 끝난다는 것.

나머지는 시뮬레이터에서 확인한다.

- 새 곡을 열면 준비 화면이 뜨고 진행률과 남은 시간이 움직인다
- 준비가 끝나면 재생이 시작되고 가사가 처음부터 완성된 상태로 보인다
- 중단하면 검색 화면으로 돌아가고 **미니플레이어가 생기지 않는다**
- 같은 곡을 다시 열면 준비 없이 즉시 들어간다
- 다른 곡 재생 중에 새 곡을 고르면 준비하는 동안 듣던 곡이 계속 재생된다

## 범위 밖

해석 품질 재설계(문맥 기반 단어 선택·뜻)는 별도 사이클로 남긴다. 그
작업은 고정된 가사 줄에 파이프라인을 돌려 결과를 파일로 찍어내는 비교
장치를 먼저 만들기로 했다 — 프롬프트 변경의 효과를 눈으로 두 줄 비교하는
것 말고 확인할 방법이 없었던 문제가 있었기 때문이다.
